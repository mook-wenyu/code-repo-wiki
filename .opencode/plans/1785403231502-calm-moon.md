# repo-wiki 实现计划 v4 — SQLite FTS5 + CLI 搜索 + Pipeline 集成

## 目的地

repo-wiki 演进为**持久化 SQLite FTS5 搜索优先 + CLI 可交互 + OpenCode Agent 共享**的代码知识平台。

## 当前状态

已完成的模块（不移改）：
- 6 语言 parser、知识图谱、LLM 生成、输出渲染、增量更新、Watch 模式
- 搜索引擎骨架：text.rs（BM25 bincode）、semantic.rs（向量 bincode）、hybrid.rs（RRF）、agent.rs（回溯）、ast.rs（AST 查询）、callgraph.rs（调用图）、ast_chunker.rs（AST 分块）
- **搜索引擎未接入 pipeline**，`search/` 模块是死代码

用户决策：
- **CLI**：添加 `search` 子命令（目前缺失）
- **网络依赖**：允许引入 `rusqlite bundled`
- **SQLite FTS5**：替换 bincode 为 SQLite FTS5 持久化
- 向量搜索保持现有 EmbeddingEngine + 内存计算（不支持 sqlite-vec 下载时）

## 修改文件清单及具体方案

### 1. `Cargo.toml` — 新增 rusqlite
```toml
rusqlite = { version = "0.32", features = ["bundled"] }
```
理由：FTS5 是 SQLite 内置扩展（bundled 编译无需系统 SQLite），零额外部署依赖。

### 3. `src/search/text.rs` — FTS5 重写（核心变更）

**结构变更**：从 `Vec<DocEntry> + HashMap<token, df>` 改为 SQLite FTS5 虚表。

```rust
pub struct TextEngine {
    conn: rusqlite::Connection,
    db_path: Option<PathBuf>,  // None 时为 :memory:
}

impl TextEngine {
    pub fn open(path: impl AsRef<Path>) -> Result<Self>;
    pub fn new_in_memory() -> Result<Self>;  // 改为 Result（建表可能失败）
    pub fn index(&mut self, node: &CodeNode, source_code: &str) -> Result<()>;
    pub fn search(&self, query: &str, limit: usize) -> Result<Vec<(CodeNode, f64)>>;
    pub fn delete(&self, name: &str) -> Result<()>;        // 新增
    pub fn update(&mut self, node: &CodeNode, source_code: &str) -> Result<()>;  // 新增
    pub fn clear(&mut self) -> Result<()>;
    pub fn doc_count(&self) -> Result<usize>;
}
```

**SQL Schema**：
```sql
CREATE VIRTUAL TABLE IF NOT EXISTS code_fts USING fts5(
    name, kind, signature, source_code,
    content='',         -- 无 content 表，纯 FTS5
    tokenize='unicode61'
);
CREATE TABLE IF NOT EXISTS code_nodes (
    rowid INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    kind TEXT NOT NULL,
    signature TEXT,
    source_code TEXT,
    file_path TEXT,
    line_start INTEGER, line_end INTEGER,
    module_path TEXT,       -- JSON 序列化
    doc_comment TEXT
);
```

**index()**：INSERT INTO code_nodes + INSERT INTO code_fts（使用同一个 rowid）

**search()**：
```sql
SELECT ... FROM code_fts
LEFT JOIN code_nodes ON code_fts.rowid = code_nodes.rowid
WHERE code_fts MATCH ?
ORDER BY rank          -- FTS5 内置 BM25 排序
LIMIT ?
```
rank 返回 float（越小越相关），逆序取 limit 条，分数归一化到 0-1。

**delete()**：DELETE FROM code_fts WHERE name=?（同步删除 code_nodes）

**clear()**：DROP TABLE code_fts; DROP TABLE code_nodes; 重建

### 6. `src/lib.rs` — pipeline 搜索集成

**run_pipeline()** 在 Phase 2 (build_graph) 后、Phase 3 (generate) 前新增：

```rust
// Phase 2.5: 构建搜索索引
if config.search.enabled {
    let index_dir = search::search_index_dir(&config);
    std::fs::create_dir_all(&index_dir)?;
    let text_engine = TextEngine::open(index_dir.join("text.db"))?;
    // 遍历所有 entity 建立索引
    for n in graph.graph.node_indices() {
        if let Some(node) = graph.graph.node_weight(n) {
            if is_searchable(&node.kind) {
                let source_code = /* 从 file_insights 获取 */;
                text_engine.index(node, &source_code)?;
            }
        }
    }
}
```

**run_incremental_pipeline()** 类似，但只对 `changed_set` 涉及的 entity：
1. 根据 changed_set 确定受影响的 entity_ids
2. 对每个 entity：先 delete 再 index（替代 update）

### 7. `src/main.rs` — CLI Search 子命令

```rust
/// 搜索代码库
Search {
    /// 查询字符串
    #[arg(short, long)]
    query: String,
    /// 返回结果数量（默认 10）
    #[arg(short = 'k', long, default_value = "10")]
    top_k: usize,
    /// 搜索引擎: text / semantic / hybrid（默认 hybrid）
    #[arg(short, long, default_value = "hybrid")]
    engine: String,
    /// JSON 格式输出（默认表格）
    #[arg(short, long)]
    json: bool,
}
```

处理逻辑：
1. 加载配置 + 打开搜索引擎（TextEngine + SemanticEngine）
2. 根据 `--engine` 选择搜索策略
3. 表格输出或 JSON 输出

### 8. `src/lib.rs` — 暴露搜索引擎给 CLI

为了 CLI `search` 能复用 pipeline 构建的索引，有两种方案：

**方案 A（推荐）**：`run_pipeline` 返回的 AnalysisResult 包含 engines
```rust
pub struct AnalysisResult {
    pub graph: KnowledgeGraph,
    pub documents: Vec<WikiDocument>,
    pub cards: Vec<KnowledgeCard>,
    pub stats: AnalysisStats,
    pub text_engine: Option<TextEngine>,   // 新增
    pub semantic_engine: Option<SemanticEngine>,  // 新增
}
```

**方案 B**：CLI search 独立初始化搜索引擎（适合已持久化的索引）

最终采用**方案 B**：CLI search 直接打开现有的索引文件，不依赖 run_pipeline 结果。这样 generate 和 search 解耦，search 命令即使在没有运行 generate 的情况下也能工作（只要索引存在）。

### 9. `src/incremental/mod.rs` — 增量索引更新

`run_incremental_update` 已返回 `changed_files`。在 `run_incremental_pipeline` 中：

1. 根据 `changed_files` 列出涉及的 entity 名称
2. 从增量 state 中读取旧 entity 列表
3. 对变更的 entity：delete + index
