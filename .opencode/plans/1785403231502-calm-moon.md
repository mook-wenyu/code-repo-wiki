## 3. 设计决策（5 项评估结论）

### 3-1 知识引擎分层（#13）→ Out of scope

Qoder 四层中：
- **用户级**（表达习惯）= Agent 侧记忆/偏好系统，不属于仓库文档 CLI 的边界；
- **任务级**（当前任务上下文）= 会话记忆，同属 Agent 侧；
- **团队级**（团队规范）= 随 Git 提交共享的 wiki_plan.yaml（notes + 作者元数据）+ config.toml，**本计划的 #1 已对等覆盖**；
- **仓库级**（架构知识）= 本工具核心产物（KnowledgeCard/Wiki）。

repo-wiki 是仓库级工具，用户/任务级依赖外部记忆系统，强行内置会引入会话持久化、用户档案等一整套不属于"Repo Wiki"的子系统。YAGNI：不做。本计划不新增任何相关代码。

### 3-2 DB Schema 文档（#10）→ 正则定位 + LLM 生成（不写 SQL 解析器）

tree-sitter 无 SQL 语法（7 语言不含）。两个候选：
- a) 轻量正则提取列/索引 → 脆：方言差异（SQLite/PG/MySQL）必然产出错误结构，且"解析交给代码"违背本项目的 LLM 驱动定位；
- b) **正则只做语句块切分，结构解析交给 LLM** → 与 Qoder 行为对等（Qoder 也是 AI 生成），代码量最小（~60 行），错误容忍由 LLM 承担。

选 b。正则仅用于从 `.sql` 迁移文件中定位 `CREATE TABLE` 语句的起止行，切分后的语句块原文 + 文件路径喂给 LLM 生成结构化 schema 文档（表结构/关系/索引，输出 markdown + mermaid erDiagram 代码块）。此正则的作用是**输入切分**，不是防御性兜底。

### 3-3 性能基准（#12）→ 扩展现有简易基准，不引入 criterion

事实修正：`benches/bench_search.rs` 已存在（Instant 循环 + `#[test]` + CI 跳过），方向正是"内置简易基准"。引入 criterion 需网络下载 + 二进制/CI 复杂度，收益与现状差异极小。决策：沿用 `#[test]` + `Instant` 模式，**扩展覆盖**：文件扫描、知识图谱构建（analysis）、FTS5 批量索引、混合搜索。criterion 的精确统计对本项目（LLM 调用占绝对大头）无意义——流水线耗时由网络 LLM 决定，本地基准只监控 CPU 侧回归。

### 3-4 多语言（#6）→ 每语言独立 LLM 生成 Wiki 页（非翻译）

- **翻译方案**成本更高：需要翻译流水线、翻译指纹追踪、增量同步三套机制，且翻译腔质量低于原生写作；
- **独立生成方案**：prompt.rs 五个模板**全部已带 `language` 参数**（prompt.rs:7,77,141,173,221），基础设施已就绪，仅差调用层循环；
- 成本控制：**KnowledgeCard 仅主语言生成一次**（卡片是 Agent 读的结构化数据，跨语言共享合理，Qoder 亦同）；Wiki 页每语言生成一次（prompt 传对应语言，复用主语言卡片摘要）。额外成本 = `expand_languages.len() × 模块数` 次 LLM 调用，默认配置为空数组（schema.rs:30）不触发，用户显式开启即接受成本。

### 3-5 wiki_plan.yaml 对齐（#1）→ 语义对齐官方，结构平铺，不做嵌套兼容

官方结构：`version / repowiki{template,notes[],documents[{title,goal,parent,hints}]} / knowledgecard{notes[]} / scope{include,exclude}`。
现有结构：顶层平铺 `notes: Option<String> / sections / documents[{title,goal,parent,include_patterns,exclude_patterns}]`（plan.rs:13-62）。

对齐决策（不向后兼容，直接改）：
- **加** `version: Option<u32>`（解析后校验 `== 1`，不匹配报错——这是格式契约不是兜底）；
- **加** `knowledgecard: Option<PlanNotes>`（卡片专用 notes）；
- **加** `scope: Option<ScopeSection>`（覆盖 config.toml 的 scope，Qoder 语义）；
- **documents 加** `hints: Option<String>`（官方字段）；
- **notes 保持 `Option<String>`** 而非官方数组：官方 `author` 字段无任何消费者（文件随 Git 提交，blame 即作者），为无消费者的字段引入数组结构违反 YAGNI；
- **sections 保留**（项目扩展：模块级 template/notes，官方没有但已有测试覆盖，见 tests/test_plan.rs）；
- **不引入 `repowiki` 嵌套节**：纯语法差异，平铺即等价，避免无谓的嵌套解析；
- 结构变更后 tests/test_plan.rs 相关断言同步更新（§5 影响表）。

#### 2.1 人工修改保护（#2）

   /// 比对磁盘文档与生成时指纹，返回人工修改的文档路径集合
   pub fn detect_manually_modified(&self) -> Vec<String> {
       self.doc_fingerprints.iter()
           .filter(|(path, fp)| Path::new(path).is_file()
               && Self::compute_file_fingerprint(Path::new(path)).map(|f| &f != *fp).unwrap_or(false))

           .collect()
   }

## 6. 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| plan.rs 结构变更破坏 tests/test_plan.rs 现有断言（编译失败） | 中 | 同 Phase 内先改测试再改代码；影响面限于该文件 |
| prompt 签名全链路改参数（5 模板 × 调用方）编译面大 | 低 | 编译器全量提示；改动集中 P1 一次完成 |
| 人工保护误判：CRLF/LF 换行差异导致指纹不匹配 | 中 | 指纹按字节 SHA256，Windows 上生成的文档与 git autocrlf 无关（写盘即字节）；文档均本工具写出，格式一致。验收时用 CRLF 仓库验证一次 |
| 白名单在生成后过滤，LLM 调用成本仍全量发生 | 低 | 与 Qoder 语义一致（官方即"严格只输出列出的页面"）；成本换确定性 |
| 多语言 LLM 调用量翻倍（expand_languages 开启时） | 中 | 默认关闭；文档中明确成本；卡片共享控制增幅为 1+langs 倍而非 2×langs |
| 非 Git 回退全量的 `changed_files` 全量语义被误用（与"无变更跳过"判断冲突） | 中 | 2.2 明确判定条件只依赖 changed_files；测试覆盖 |
| SQL 正则切分错切（`;` 在字符串字面量内） | 低 | 语句块只作 LLM 输入，错切导致 LLM 少看一段而非崩溃；本项目 LLM 驱动，可接受（在 schema.rs 注释注明边界） |
| 10,000 文件上限测试耗时 | 低 | 抽 scan_with_limit 内部函数，测试用小数上限 |
| 插件 TS 无类型检查/无 CI | 中 | 保持薄壳（只传参数+解析输出），核心逻辑全在 Rust 侧 |
| 基准扩展后 `cargo test` 默认会跑 bench（CI 跳过已实现） | 低 | 沿用现有 CI 跳过模式 |
| 旧 generation_state.json 无 protected_docs 字段 | 低 | serde default 兼容读入（迁移兼容，非防御） |

## 7. 最终验收步骤（端到端）

前置：`cargo build --release`，`$env:PATH` 含 target/release；临时 git 仓库 A（多语言 + 混合源码）。

1. **bug 修复**：`repo-wiki generate -o tmp-out` → tmp-out/wiki/zh/ 存在；`repo-wiki uninstall-from-opencode`（无 --force）退出码非 0 且提示；`--force` 通过；
2. **wiki_plan**：仓库根放 wiki_plan.yaml（version: 1、notes、knowledgecard.notes、documents 白名单 2 页、scope.include `["src/**"]`）→ generate → 页面含 notes 文本、白名单外无输出；version: 2 → 报错退出；
3. **ApiRef**：sections 指定某模块 api-ref → 该模块 wiki 页含接口/参数段落；api.md 存在且含公开实体签名；
4. **人工保护**：手动改 wiki/zh/某模块页 → update（提交一次代码变更）→ 该页保留人工内容、其余更新；`generate --force` → 全部覆盖；
5. **非 Git**：普通目录 update → 日志显示回退全量且 wiki 产出；
6. **限制项**：临时 10,001 文件目录 generate → 报错退出且信息明确；
7. **/knowledge**：`card modify <模块> --instruction "补充错误处理说明"` → 卡片文件内容变化且结构完整；`card rewrite` 同；`card supplement` 追加；
8. **进度**：`repo-wiki generate --progress-json` → 输出 8 行单调递增 JSON；
9. **多语言**：expand_languages=["en"] → wiki/en/ 页面为独立生成（非主语言复制）；
10. **图表**：assets/diagrams/call-graph.mermaid 与 module-deps.mermaid 均存在且可渲染；
11. **Schema**：临时 .sql 迁移 → schema 文档含表结构与 erDiagram；
12. **回归**：`cargo test`（全部通过）、`cargo clippy -- -D warnings`（无警告）、`cargo test --test bench_search -- --nocapture`（本机跑通）。
