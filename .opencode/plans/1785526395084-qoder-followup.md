## 4. Phase 3 — watch 事件折叠与测试补全

### 3.1 同路径跨 kind 事件折叠

**文件**: `src/incremental/watch.rs`(aggregate_events 后新增 fold_events)
**现状**: 同路径 Modified+Deleted 产出两 WatchEvent → lib.rs:446-463 逐事件串行跑两次完整 pipeline(双倍开销,R15)。
**改动**: 折叠规则(按最终态语义,同路径跨 kind):
- Modified + Deleted → Deleted(文件已不存在)
- Created + Deleted → Deleted
- Modified + Created → Modified(最终存在,已修改)
- 同 kind 保持现有去重合并(watch.rs:94-113 不变)
不同路径事件保持独立;不改变 Deleted 直入清理语义(lib.rs:275-277)。
**注意**: 折叠发生在聚合之后、回调之前,`process_batch` 纯函数内(见 3.3)。
**验证**: cargo test 全绿(含新增)。

### 3.2 折叠规则测试
