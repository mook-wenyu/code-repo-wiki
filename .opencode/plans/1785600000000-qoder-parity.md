## 官方语义锚点（网络研究确认）

1. wiki_plan.yaml：documents 是**严格页面白名单**（非建议），parent 决定页面树，notes 带 author
2. 三更新路径是**独立的显式用户动作**：更新=代码变更→仅重建受影响页；同步=Git 内容→Wiki 合入；人工修改=标记保护、永不覆盖、**反向同步到对应知识卡片**
3. 产物布局：`.qoder/repowiki/` 根 + wiki_plan.yaml + `repowiki/{zh,en}/` 按语言
4. 硬限制：10,000 文件、仅 Git 仓库且 ≥1 提交、仅 zh/en 两种语言
5. **官方无"用户级/团队级/仓库级/任务级"四层说法**：实际是 Repo Wiki + 知识卡片 + Memory 三类来源；企业版按仓库+分支组织

## Phase 0 — 收敛与重构（先清死代码，再补功能）

### 0.1 删除 `src/search/ast_chunker.rs`（F2）

**文件**: `src/search/ast_chunker.rs`（删）、`src/search/mod.rs:6`（删声明）
**理由**: 零消费 + 与 chunk.rs 职责命名重叠；chunk.rs 已承担模块级 AST 分块职责。YAGNI。
**注意**: 删除前确认 `ast.rs` 的 Query API 仍在（agent 依赖）；只删 ast_chunker。
**验证**: `cargo test` 191 项不减（ast_chunker 测试随文件删除，无外部依赖）。

### 0.2 接入 `callgraph.rs`（F1）

**文件**: `src/search/agent.rs`
**现状**: SearchAgent 组合 text/semantic/ast；callgraph 零消费。
**改动**: SearchAgent 增加 `call_graph: Option<CallGraph>` 字段与 `with_callgraph()` 构造器；`search()` 主流程后追加"调用链补全"阶段——对 top-k 结果中的实体，用 `caller_of/callee_of` 收集调用者/被调用者并附到命中（`SearchHit` 增 `callers: Vec<String>`/`callees: Vec<String>` 可选字段）。
**理由**: 官方"引用关系图（函数调用链、文件依赖）"能力落地的可查询形态；复用已写好的 4 个方法，不新增图算法。
**测试**: agent.rs 增 `test_callgraph_enrichment`：构造小图（a→b→c），查询 b，断言 hit 含 caller a 与 callee c。
**注意**: SearchHit 是跨模块结构（lib.rs:589-611 使用），字段必须 `#[serde(default)]` 保持 JSON 兼容（无存量用户，但保持最小 diff）。

### 0.3 overview.md 独立生成（F5）

**文件**: `src/generate/wiki.rs`（新增 `generate_overview`）、`src/output/mod.rs:138-143`（替换拼接）
**现状**: `documents.first()` 是第一个模块页（白名单过滤可能换序，内容不稳定）。
**改动**:
1. `wiki.rs` 新增 `overview_prompt(graph, config)` 模板（复用现有 prompt 风格：输入 = 模块列表 + 模块依赖摘要，输出 = 项目概览，含技术栈/目录结构/核心模块三节）
2. `generate/mod.rs` 全量与增量两处，在架构概览旁生成 overview 文档（`WikiDocument` 增 kind 判别或复用 `ArchitectureOverview` 变体——若复用，确认 output/mod.rs 的分派逻辑）
3. `output/mod.rs` 删除拼接逻辑，改走 `write_document` 路径（含指纹记录、保护跳过、多语言独立生成）
**测试**: `tests/test_overview.rs`（新）：
1. `test_overview_independent` — mock LLM 下 overview 内容来自 overview prompt 而非第一个模块页
2. `test_overview_protected` — overview 受 doc_fingerprints 保护，人工修改后 update 不覆盖

### 0.4 api.md 只写主语言（F3）

**文件**: `src/output/mod.rs:129-136`
**现状**: N 语言 N 份逐字节相同文件 + state.rs 每语言各记一份指纹（4 倍维护成本）。
**改动**: 多语言循环中 api.md 仅在主语言写一份（`if lang == &primary`）；单语言行为不变。
**理由**: api.md 内容 = 实体签名/文档注释（markdown.rs:65-72），与语言无关；官方按语言独立的是叙事页面。
**注意**: 需同步确认 state.rs 指纹记录路径与写盘路径一致（记录 api 时若 multi-lang 只写一份，指纹也记一份）。
**测试**: 更新 `tests/test_multilang.rs`：断言 `wiki/en/api.md` 不存在、`wiki/zh/api.md` 存在。

## Phase 1 — 三更新路径语义补全

### 1.1 watch.rs 事件类型显式化（F4）

**文件**: `src/incremental/watch.rs:23-27,54-65`、`src/lib.rs:175-190`
**现状**: 回调 `Fn(Vec<PathBuf>)`；删除靠下游 exists() 推断（rename 可能误判为 delete+add）。
**改动**:
1. 新类型 `WatchEvent { paths: Vec<PathBuf>, kind: ChangeKind }`（ChangeKind 复用现有 Created/Modified/Deleted）
2. 回调签名改 `Fn(WatchEvent)`
3. `lib.rs::run_watch` 将事件 kind 传入 `run_incremental_pipeline`（新增可选参数 `change_kind`），`incremental/mod.rs` 中 Deleted 事件直入删除清理路径，避免 exists() 推断
**测试**: watch.rs 增 `test_watch_event_kind_preserved`：构造 DebounceEvent 数组含 Modify+Remove，断言聚合后 kind 正确。

### 1.2 Git 内容同步命令（sync）

**文件**: `src/main.rs`（新子命令）、`src/commands.rs` 或 `src/incremental/mod.rs`（新 `sync_from_git`）
**官方语义**: Git 目录中直接编辑 .md 后，手动触发"同步"以 Git 内容为准合入 Wiki；覆盖团队 pull 共享知识的场景；受保护页面保留人工版。
**改动**:
1. `Sync` 子命令（`repo-wiki sync`）：扫描产物目录（wiki/{lang}/、cards/{lang}/）与 git 工作区差异
2. 逻辑：对每个 .md 产物，比较工作区内容 vs 上次生成指纹（doc_fingerprints）；内容不同 → 更新指纹 + 保留工作区内容（即"以 Git 内容为准"）+ 若页面在 protected_docs 则跳过
3. 本质上 = 重新加载工作区 .md 内容到指纹库，不触发 LLM 重生成
**测试**: `tests/test_git_sync.rs`（新）：
1. `test_sync_updates_fingerprint` — 修改产物 .md 后 sync，指纹更新、内容保留
2. `test_sync_skips_protected` — 受保护页面 sync 不改变

### 1.3 人工修改反向同步到卡片

**官方语义**: 人工修改的 .md 不被自动更新覆盖，且**反向同步到对应知识卡片**。
**现状**: `state.rs:181-186 detect_manually_modified` 只检测+跳过，无反向同步。
**改动**: `incremental/mod.rs` 增量流程中，检测到人工修改时：
1. `tracing::warn!` 报告（现有）
2. 新增：将人工修改页面的内容摘要（前 N 行 + 变更行）写入对应卡片的 `todo_notes` 或新增 `pending_manual_edits: Vec<String>` 字段（KnowledgeCard 扩展），下次生成时作为 LLM 输入（"有人工修改待同步"）
**理由**: 完整实现官方"反向同步到对应知识卡片"语义；改动小而明确。
**测试**: `tests/test_protected_files.rs` 增 `test_manual_edit_recorded_in_card` — 人工修改页面后 update，断言卡片出现修改记录。
